# Pawmigo 前端流程走查记录

更新时间：2026-06-03

## 走查范围

仅覆盖 `pawmigo-mini` 前端原型与小程序页面流转。当前后端数据尚未接入，页面使用 `src/data/mockData.ts` 中的模拟数据验证故事线、页面承接和状态反馈。

## 已拉通的核心用户旅程

### 新用户进入

`启动页 -> 登录/注册 -> 创建宠物档案 -> 权限说明 -> 附近地图`

用户能完成从首次进入到开启地图发现的完整路径。验证码按钮有即时反馈，社交登录入口会进入建档流程。

### 附近发现与邀约

`附近地图 -> 宠物详情 -> 等待回应 -> 匹配成功 -> 集合点确认 -> 偶遇进行中 -> 消息沟通 -> 反馈 -> 钱包`

地图、宠物详情、匹配结果和偶遇闭环现在统一使用 mock 数据中的宠物、距离、集合点和匹配理由，避免同一条链路中出现不同宠物名称或地点。

### 社区沉淀

`圈子 -> 发帖 -> 贴纸编辑 -> 回到圈子`

圈子页使用多条模拟动态，支持从动态、贴纸和发布入口进入对应页面。

### 组队

`组队列表 -> 队伍详情 -> 创建队伍 -> 队伍详情`

队伍列表接入统一 mock 数据，卡片和按钮都能进入详情，新增按钮能进入创建流程。

### 我的、安全与钱包

`我的 -> 钱包 / 奖杯墙 / 队伍 / 设置 / 安全中心`

`钱包 -> 赚骨头 / 兑换中心`

`安全中心 -> 隐私安全 / 紧急求助`

个人中心、钱包、安全中心已经形成可返回、可继续跳转的闭环。

## 这轮发现并修复的问题

- 页面之间数据口径不一致：地图、详情、匹配、偶遇消息中出现不同宠物名和地点。
- 圈子内容过薄：只有一条写死动态，无法体现社区内容流。
- 组队列表使用页面内硬编码数据，和统一 mock 数据割裂。
- 部分按钮只有视觉样式，没有反馈或承接页。
- 路由检查只能验证页面存在，不能验证关键旅程相邻跳转。

## 已新增的前端质量保障

新增 `npm run check:routes`，覆盖：

- 已注册页面数量
- 页面跳转目标是否存在
- 是否有注册但不可达页面
- onboarding、偶遇、社区、组队、个人、安全、钱包等关键路径的相邻跳转是否存在

新增 `npm run audit:weapp-ui`，覆盖：

- 自动执行 `npm run build:weapp`
- 验证 `project.config.json` 指向 `dist/`
- 验证 `dist/app.json` 已生成，避免微信开发者工具导入错误目录后出现 `app.json is not found`
- 执行 `npm run check:routes`
- 在 `pawmigo-mini/audit/weapp-ui/` 生成本次 UI 审核报告

需要连同微信开发者工具截图一起取证时，使用：

```bash
cd pawmigo-mini
npm run audit:weapp-ui:open
```

该命令会打开微信开发者工具并保存桌面截图。微信开发者工具应导入 `pawmigo-mini` 目录，不要导入仓库根目录。

手动走到某个页面后，需要追加命名截图时，使用：

```bash
cd pawmigo-mini
npm run audit:weapp-ui:capture -- --capture=splash --out=audit/weapp-ui/manual-review
```

其中 `--capture=` 用于命名当前截图，`--out=` 用于把多张截图放进同一个审核包。该命令会跳过构建和路由检查，避免刷新或打断微信开发者工具模拟器的当前页面。

需要把设计或运行问题写进同一个审核报告时，追加 `--finding=`：

```bash
cd pawmigo-mini
npm run audit:weapp-ui:capture -- --out=audit/weapp-ui/manual-review "--finding=登录页禁用态按钮对比度偏低"
```

## 后续产品优化建议

- 增加全局流程状态：记录当前选中的宠物、队伍、帖子和偶遇对象，替代现在的静态默认对象。
- 给筛选、设置、反馈、兑换增加本地状态变化，让用户看到选择被保存。
- 为发帖、创建队伍、宠物档案表单加入最小表单校验与成功态。
- 增加空状态、加载态和失败态，覆盖网络接入后的真实边界情况。
- 建议下一步优先实现一个前端 mock store，把 `mockData.ts` 从“展示数据”升级为“可交互状态”。
